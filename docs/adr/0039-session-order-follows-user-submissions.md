# Session 列表按用户最后发送时间排序

多个 Session 并行运行时，按 runtime activity 排序会让会话不断交换位置，破坏导航的位置记忆。Project 与 Chats 的 Session 列表改为按用户最后一次成功发送消息的时间倒序；普通发送、Queue 和 Steer 都算，运行状态和未读结果只影响提示，不参与排序。此决策替代 ADR-0008、ADR-0011 中的排序规则，不改变归档和状态指示规则。

- 用户成功提交时更新排序时间；助手输出、工具执行、完成／失败、打开会话、改标题、草稿编辑不更新。
- Queue 按提交时间计，开始处理和撤回不再触发排序。没有发送记录的新 Session（包括 Fork）按创建时间排。
- 列表时间标签与排序使用同一个时间。最近聊天活动时间继续独立服务于投影新鲜度，不混用。
- 最后发送时间随 Session Projection 保存，冷启动和恢复后保持一致。旧投影首次读取时从 Pace 的 Session Event Journal 中回填用户消息／Steer 时间；旧日志没有 Queue 提交边界时，只能使用其用户消息回显时间。没有可用历史的旧投影保留原时间，不使用本次打开时间，也不修改 Pi 的会话记录。

不新增「需要你处理」分区；本次只调整排序，保留现有运行中和未读指示。
