# New Chat 与侧栏交互修复

日期：2026-09-07。验证环境：通过 `bun run dev` 启动的 Electron 开发实例。检查方式包括 Computer Use 真实点击、键盘输入、辅助功能树、开发窗口截图及自动化测试。

## 问题与根因

| 场景 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 已添加项目后，从全局入口新建对话 | 默认草稿目标为 null，但发送要求有效目标 | 全局 New Chat 默认 No project；项目旁加号默认对应项目 |
| 不同入口和无项目侧栏 | New Session / New Chat 混用，Chats 下存在多余 Chat 父层 | 统一为 New Chat，Chats 直接列出无项目会话 |
| 侧栏列表过长 | 缺少整个 Chats / Projects 分组的折叠操作 | 两组独立折叠并保存本机状态，标题栏均采用折叠箭头与加号 |
| 目标改变后仍显示旧校验错误 | 错误只在项目选择器回调中清除，侧栏改变目标不经过该回调 | 校验按当前目标派生，并关联到项目控件 |
| 点击建议后继续输入 | 只更新文字，没有聚焦输入框 | 填入后聚焦输入框，光标位于末尾 |
| 项目与执行方式选择 | 项目菜单向上靠近模型栏；Local / Worktree 缺少影响说明 | 项目菜单向下打开；选中项目后显示 Project folder / Git worktree 及说明 |
| 新建草稿显示旧会话资源 | Dock 挂载条件没有排除草稿视图 | 草稿页隐藏旧会话的 Dock 入口和面板 |
| 模型失败后恢复操作不清楚 | 原始错误直接展示，缺少设置与重试入口 | 可读说明、折叠详情、Provider settings、模型选择及重试入口 |
| 模型切换尚未完成即重试 | 模型配置 RPC 与发送请求没有排序 | 重试等待进行中的模型切换完成 |
| 插入菜单过长 | 技能、插件和命令集中在长菜单，缺少搜索 | 精简一级入口，技能与插件列表可搜索，技能说明默认最多两行 |

现场验证没有确认项目菜单存在 z-index 遮挡，因此这里只记录固定向下展开所解决的阅读干扰，不将其描述为已修复的层级遮挡问题。

## 行为边界

- 改变提交目标保留全局草稿文本；被删除项目的草稿保持未选择状态，要求明确选择新目标，不自动转为无项目对话。
- Chats 标题栏的加号新建无项目对话；Projects 标题栏的加号打开原生目录选择器。移除独立的 Add Project 列表行，收起分组后加号仍可用。
- 分组折叠不切换当前会话，也不覆盖项目内部的展开偏好。折叠按钮提供键盘操作、悬停提示和无障碍展开状态。
- 技能描述来自 Pi SDK，完整描述仍参与搜索。插件显示可读名称，但插入时保留原始标识。
- 仅最新且允许交互的失败请求提供重试，沿用原消息和附件，保留未发送的后续草稿；组件防止重复点击并展示重试启动错误。
- 新增的 ChatRunFailure 及相关变体已注册到 Design 页；侧栏调整复用 Astryx SideNavSection、IconButton 和 Stack，不新增共享原语。

## 验证

- `bun run test --maxWorkers=4`：完整测试覆盖。
- `bun run build`：类型检查及 Electron 主进程、preload、renderer 构建。
- 实际开发窗口验证了目标默认值、执行说明、建议后续写、技能搜索、错误详情、Provider 设置入口、分组折叠与刷新恢复，以及 Projects 加号打开目录选择器后取消。
- 初次模型请求因开发环境的无效凭据返回 401。凭据没有修改，成功模型回复不属于本次已验证结果；真实文件上传与 Worktree 创建也未在现场执行。
